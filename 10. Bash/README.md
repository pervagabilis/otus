# Bash

## Цель

Написать bash-скрипт для cron, который раз в час разбирает access-лог веб-сервера и формирует отчёт.

## Текст задания

Написать скрипт для cron, который раз в час формирует отчёт и отправляет его на заданную почту. Отчёт должен содержать (всё — с момента последнего запуска):

- IP-адреса с наибольшим числом запросов;
- запрашиваемые URL с наибольшим числом запросов;
- ошибки веб-сервера/приложения;
- HTTP-коды ответов с указанием их количества.

Скрипт должен предотвращать одновременный запуск нескольких копий. В письме должен быть указан обрабатываемый временной диапазон. В критериях оценки: трапы и функции, а также `sed` и `find`.

## Выполнение

### 1. Стенд

Отправку на почту не делаю: скрипт только формирует отчёт и сохраняет его в `/var/lib/web-report/reports/report-<дата>.txt`. В начале отчёта указаны обработанные строки лога и временной диапазон.

Nginx на стенде нет. Вместо него лог из задания подаю в `/var/log/nginx/access.log` частями, как будто сервер его дописывает.

```bash
vadim@ubuntu-otus:~/otus/10. Bash/vm$ vagrant up
vadim@ubuntu-otus:~/otus/10. Bash/vm$ vagrant ssh
```

### 2. Что значит «с момента последнего запуска»

Лог из задания за 14–15 августа 2019 года. Если отсчитывать «последний час» от текущего времени, в отчёт не попадёт ни одной строки. Поэтому скрипт запоминает, сколько строк лога уже обработал, в файле `/var/lib/web-report/position`. При следующем запуске берёт строки с `position + 1` до текущего конца:

```bash
tail -n +"$((last + 1))" "$LOG" | head -n "$((total - last))" > "$NEW"
```

`head` нужен на случай, если сервер допишет строки между `wc -l` и `tail`. Без него эти строки попадут в отчёт, но в `position` не посчитаются и придут второй раз через час.

Если лог стал короче, чем `position`, значит, его ротировали, и скрипт читает его с начала.

Отчёт сначала пишется во временный файл, потом переносится в каталог отчётов, и только после этого записывается позиция. Если отчёт сохранить не удалось, эти же строки попадут в следующий.

Временной диапазон — время из первой и последней обработанной строки. Достаю его через `sed`:

```bash
sed -n "$1"'s/^[^[]*\[\([^]]*\)\].*/\1/p' "$NEW"   # $1 = 1 или $
```

### 3. Разбор строки лога

Сначала резал строку по пробелам: код ответа в поле `$9`, URL в `$7`. Проверил на всём логе:

```bash
vadim@ubuntu-otus:~/otus/10. Bash$ awk '{print $9}' access-4560-644067.log | sort | uniq -c | sort -rn
    498 200
     95 301
     51 404
     11 "-"
      7 400
...
```

Кода `"-"` не бывает. Это строки, где вместо HTTP-запроса пришли бинарные данные (например, TLS-handshake на обычный порт), в них другое число пробелов:

```text
60.208.103.154 - - [14/Aug/2019:11:59:33 +0300] "\x16\x03\x01\x00Z\x01\x00\x00V\x03\x01]S..." 400 ...
```

Поэтому режу строку не по пробелам, а по кавычкам (`awk -F'"'`). Nginx экранирует кавычку внутри запроса как `\x22`, так что поля стоят на месте:

- `$2` — запрос целиком, `GET /wp-login.php HTTP/1.1`, из него беру URL;
- `$3` — ` 400 173 `, первое слово — код ответа.

Каждый раздел отчёта — отдельная функция: `top_ips`, `top_urls`, `errors`, `http_codes`.

Ошибками считаю ответы 4xx и 5xx. `error.log` к заданию не приложен, поэтому других источников ошибок у меня нет. В отчёт идёт код, запрос и сколько раз он встретился. Запрос обрезаю до 60 символов, иначе бинарный мусор растягивается на пол-экрана.

### 4. Защита от двойного запуска

```bash
exec 9> "$LOCK"
if ! flock -n 9; then
    echo "web-report: уже запущен, выходим" >&2
    exit 1
fi
```

Блокировка держится на открытом дескрипторе 9 и снимается ядром, когда процесс завершается, даже если его убили через `kill -9`. Поэтому lock-файл удалять не нужно и «зависшего» lock-файла не бывает.

`trap ... EXIT` удаляет временные файлы с новыми строками и текстом отчёта при любом выходе из скрипта.

### 5. Cron и старые отчёты

```text
# /etc/cron.d/web-report — отчёт по логу nginx раз в час
SHELL=/bin/bash
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
0 * * * * root /usr/local/bin/web-report.sh
```

Отчёты старше недели удаляет `find`:

```bash
find "$REPORT_DIR" -name 'report-*.txt' -mtime +7 -delete
```
