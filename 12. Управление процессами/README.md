# Управление процессами

## Цель

Научиться получать информацию о процессах напрямую из `/proc`, без утилит `ps` и `top`.

## Текст задания

Выбран вариант 1. Реализация аналога `ps ax`:

- создать скрипт, который получает информацию о процессах через файловую систему `/proc`;
- вывести не менее следующих полей: PID, PPID, состояние процесса, имя или команда запуска;
- проверить работу скрипта на запущенной системе и зафиксировать пример результата.

## Выполнение

### 1. Откуда брать данные

Каждый процесс в системе — это каталог `/proc/<PID>/`. Мне нужны два файла из него:

- `/proc/<PID>/stat` — одна строка со всеми полями процесса. Поле 1 — PID, 2 — имя процесса в скобках, 3 — состояние, 4 — PPID;
- `/proc/<PID>/cmdline` — команда запуска, аргументы разделены символом `\0`. У потоков ядра файл пустой, поэтому для них, как и `ps`, вывожу имя в квадратных скобках.

Сначала хотел брать имя из `/proc/<PID>/comm`, а состояние и PPID из `/proc/<PID>/status` через `grep`. Но это несколько внешних процессов (`cat`, `grep`, `awk`) на каждый PID. `stat` читается встроенным `read` за одно чтение, и скрипт не запускает внешних команд внутри цикла.

### 2. Разбор stat

Проблема в имени процесса: оно может содержать пробелы и скобки, поэтому резать строку по пробелам нельзя. Проверил на копии `sleep` с неудобным именем:

```bash
vagrant@otus-hw12:~$ cp /bin/sleep '/tmp/a b) c'
vagrant@otus-hw12:~$ '/tmp/a b) c' 60 &
vagrant@otus-hw12:~$ cat /proc/$!/stat | cut -d' ' -f1-8
12769 (a b) c) S 12748 12748 12748
```

Если резать по пробелам, получается состояние `b)` и PPID `c)`.

Имя процесса стоит между **первой** `(` и **последней** `)`, а после последней `) ` идут только числа и буква состояния. Режу строку встроенными средствами bash:

```bash
comm=${stat#*(}                # убираю всё до первой "("
comm=${comm%)*}                # убираю всё от последней ")"
read -ra f <<< "${stat##*) }"  # поля после последней ") " — в массив, f[0] = поле 3
state=${f[0]}
ppid=${f[1]}
```

### 3. Сортировка по PID

`/proc/[0-9]*` раскрывается в алфавитном порядке: `1`, `1026`, `11`… Поэтому сначала собираю список PID и сортирую его через `sort -n`, а потом прохожу по нему циклом.

### 4. Запуск

Скрипт работает на любой Linux-системе:

```bash
bash psax.sh
```

На стенде копия скрипта лежит в `vm/`, поэтому в VM она доступна как `/vagrant/psax.sh`:

```powershell
PS C:\DEV\otus\12. Управление процессами\vm> vagrant up
PS C:\DEV\otus\12. Управление процессами\vm> vagrant ssh
```

Процесс с неудобным именем скрипт показывает так же, как `ps ax`:

```bash
vagrant@otus-hw12:~$ bash /vagrant/psax.sh | grep -F '/tmp/a b'
12769	12748	S	/tmp/a b) c 60
vagrant@otus-hw12:~$ ps ax | grep -F '/tmp/a b' | grep -v grep
  12769 pts/1    S+     0:00 /tmp/a b) c 60
```

Количество процессов совпадает с `ps ax` (считаю только строки, начинающиеся с PID):

```bash
vagrant@otus-hw12:~$ bash /vagrant/psax.sh | grep -cP '^\d+\t'
146
vagrant@otus-hw12:~$ ps ax --no-headers | wc -l
146
vagrant@otus-hw12:~$ time bash /vagrant/psax.sh > /dev/null

real	0m0.066s
user	0m0.055s
sys	0m0.013s
```

Я написал скрипт, который по данным из `/proc` выводит PID, PPID, состояние и команду запуска всех процессов. Проверил его на процессе с пробелами и скобками в имени, результат совпал с `ps ax`.
